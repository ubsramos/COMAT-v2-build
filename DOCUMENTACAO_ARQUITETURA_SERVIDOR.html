Guia de Engenharia e Arquitetura de Servidor — Gateway Reverse Proxy

O COMAT v2 adota a arquitetura corporativa de Gateway Reverse Proxy Multi-Tenant. O servidor de borda (Nginx Host) escuta nas portas públicas 80 e 443, gerenciando os certificados SSL e despachando as conexões de forma segura para containers Docker isolados em portas locais fechadas.

2. Entendendo a Coluna PORTS no Comando "docker ps"

$ sudo docker ps -a
PORTS: 9000/tcp, 127.0.0.1:8033->80/tcp

A. 127.0.0.1:8033 -> 80/tcp (Porta de Aplicação)

• 127.0.0.1 (Loopback): A porta está restrita à memória local do servidor. Ninguém na rede externa consegue acessá-la diretamente, garantindo 100% de blindagem.

• 8033 ➔ 80: O Nginx Host recebe na porta 80 pública e despacha internamente para a 8033, que o Docker entrega na porta 80 interna do container.

B. 9000/tcp (Porta FastCGI do PHP-FPM)

• A porta 9000/tcp não possui seta (->). Isso significa que ela opera exclusivamente dentro da rede do container para comunicação entre o Nginx e o PHP 8.2-FPM.

• Zero Conflito: Não ocupa portas da máquina física e não interfere em nenhum outro software do servidor.

3. Vantagens Estratégicas desta Arquitetura

Multi-App Real
10+ Containers

Cada sistema roda em uma porta interna (8033, 8034, 8035...) sob o mesmo IP.

SSL Centralizado
Borda Única

Certificados gerenciados no Host (/etc/nginx/ssl/) sem alterar containers.

Segurança Máxima
127.0.0.1

Containers não ficam expostos à internet direta.

Guia de Configuração e Acesso Administrativo

1. Configuração de DNS (Apontamento de Rede)

Tipo Nome / Host Destino / IP Finalidade
A comat.aspa.org.br 192.168.15.4 (IP do Servidor) Roteia o domínio oficial para o Gateway Nginx Host
A (Opcional) *.aspa.org.br 192.168.15.4 (IP do Servidor) Wildcard para futuros sistemas no mesmo servidor físico

2. Acesso ao Terminal e Comandos Dentro do Container Docker

# 1. Abrir Terminal Interativo (Shell) dentro do container:   sudo docker exec -it comat_v2_app sh
# 2. Visualizar logs em tempo real (Nginx + PHP):            sudo docker logs -f comat_v2_app
# 3. Testar sintaxe do Nginx interno:                        sudo docker exec -it comat_v2_app nginx -t
# 4. Inspecionar status detalhado do container:              sudo docker inspect comat_v2_app

3. Tabela de Portas, Serviços e Diretórios

Serviço Porta Escopo Localização / Configuração
Nginx Host (Gateway) 80 / 443 Público / Rede Local /etc/nginx/sites-available/comat_v2.conf
COMAT v2 (Docker) 8033 Interno (127.0.0.1) Container comat_v2_app (/var/www/html)
MySQL Server Host 3306 Local / Docker Gateway Base comat_db (Ubuntu Server)
Certificados SSL - Host Ubuntu /etc/nginx/ssl/

4. Como Ativar Certificado SSL / HTTPS

Opção A: Certificado Próprio (.crt / .key)

1. No install_server.sh, configure USAR_SSL="sim", SSL_CERT_PATH e SSL_KEY_PATH.

2. Execute: sudo bash install_server.sh

Opção B: Let's Encrypt / Certbot Automático

Com o domínio apontado, execute:

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d comat.aspa.org.br

5. Comandos Rápidos de Diagnóstico no Servidor Host

# Status do Nginx Host:    sudo systemctl status nginx && sudo nginx -t
# Recarregar Gateway:      sudo systemctl reload nginx
# Status dos Containers:   sudo docker ps -a
# Atualizar Aplicacao:     cd ~/comat-build && bash atualizar.sh
